# F375 — Pinned HTTPS transport for a separately signed recovery witness

Implements a **dormant** network implementation of the F374 `IndependentSignedWitnessTransport` interface, but **does not configure or bind it** to Laravel routes, public login, middleware, scheduled jobs, the production server, or any VPS.

The candidate accepts only a server-configured **HTTPS** DNS endpoint with the fixed path `/v1/portal/recovery-witness`, no query string, fragment, userinfo, redirects, IP literals, local-only hostname or custom port. An operator-supplied SHA-256 TLS **SPKI pin** is mandatory, in addition to curl's normal CA chain and hostname checks. Proxy usage, cookies, automatic redirect following, HTTP downgrade and caching are disabled. Connections and responses have tight deadlines and size limits; the response must have HTTP 200, JSON content type, and an exactly shaped F369 witness envelope. All network/decoder errors are sanitized to `Independent witness unavailable`.

**Two separate trust checks:** the transport pin validates the TLS server connection. The existing **Ed25519 F369 signature verifier** must then check the receipt's scope, sequence, expiry and independently pinned signing key. TLS alone does not authorize a Portal session, business permission or restore.

A dedicated GitHub-hosted TLS fixture exercises real PHP curl over localhost HTTPS with an ephemeral self-signed certificate and SPKI pin, plus an ephemeral Ed25519 signing key. The test verifies positive signed data in a **NO SERVING** diagnostic, and rejects tampered signatures, HTTP redirect, wrong status/MIME, malformed/oversized JSON, timeout, wrong TLS SPKI, invalid endpoints, IP literals and query injection. Test-only CA bundle and DNS resolver overrides are only accepted under explicit GitHub-hosted CI markers and a fixed reserved hostname. **Do not use the test leaf certificate or test signing key anywhere else.**

**Still open / NO-GO:** No approved independent external service URL, transport mTLS/client-auth mechanism, actual signing key/custody, durable witness high availability, rotation, external epoch write authority, network partition protocol, per-tenant credential, always-on serving fence, or full restore/DR security review exists. This candidate must remain unbound and unmerged until those are approved. It does not change the VPS, DNS, customer accounts, `main`, public traffic or recurring cost. Issue #64 remains blocking.
