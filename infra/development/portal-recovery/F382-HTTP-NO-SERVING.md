# F382 — HTTP no-serving witness fence demonstrated inside real Laravel

F381 proved that Portal PG18 session and grant checks can be observed through an independent **synthetic** signed HTTPS Worker in isolated CI. F382 tests the next critical interface: **even a perfect-looking observation MUST NOT be mistaken for HTTP or business authorization**.

F382 adds the narrow `PortalWitnessOnlyIdentityRead` diagnostic interface and marks the F381 `NonceBoundPortalIdentityReadCandidate` as its implementation. It adds a **dormant, deliberately non-activatable** `PortalWitnessNoServingHttpGuard` class that can optionally inspect **only a server-side Laravel encrypted session** under `portal.browser_auth`. The guard **never calls the request handler** and always returns **503** `{"error":"portal_not_ready"}` with private no-store, anti-indexing, frame-denial and no-sniff headers. A maliciously optimistic witness report with `canAuthorizeHttp=true` **does not change this response**. Malformed or missing session, unavailable SQL, invalid signed evidence or thrown exceptions also fail closed.

The Laravel feature test registers a **temporary test-only** route and supplies an in-memory fake witness report. It verifies a server-side business session, absent/malformed sessions, browser-supplied fake bearer/query tokens, errors containing supposed sensitive data, and both positive-looking and negative-looking witness statuses. **No test can receive 2xx or reach the inner controller.** A separate test and CI static check assert there are no bindings to this class or contract under the application's production routes, bootstrap or service providers; the only persistent route stays `/up`.

This middleware is a **test proof of NO SERVING**, not a path to launch. It is not registered, and there is no positive authorization branch in this code. F382 does not wire real HTTP to F381, install PostgreSQL migrations, connect to live Cloudflare Workers, perform online off-host signing, prove distributed atomicity/race-free revocation, or close security issue #64. Those require independent signers, a trusted production publisher, on-request enforcement for *all* login/session/grant/resource boundaries, AppSec/DBA checks, operational revocation and recovery review.

No merge to main, VPS, DNS, public routes, deploy, real credentials, chargeable Cloudflare use, or customer data are involved.
