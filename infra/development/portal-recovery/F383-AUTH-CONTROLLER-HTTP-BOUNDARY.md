# F383 — Real Laravel Portal authentication controller paths tested behind NO-SERVING witness fence

F382 introduced a dormant HTTP middleware which **always** denies serving, regardless of whether F381/F380/F379 witnessed the private PostgreSQL session as active. F383 proves the same rule across the **real existing Laravel controller code** rather than a generic test handler.

A Laravel feature test creates temporary test-only routes (not written to `routes/web.php`) for the existing `PortalBrowserAuthController` entrypoints: CSRF token, password, MFA, current session and logout. Each route is grouped under the existing `web` middleware, the HTTPS/CSRF `PortalBrowserAuthGuard`, and F382 `PortalWitnessNoServingHttpGuard` in that order. The test binds synthetic fake identity and witness readers **only inside the PHPUnit app container**. The fake identity intentionally would issue 64-hex pending/business session references and return authenticated=true if its methods were reached; the fake witness maliciously claims `canAuthorizeHttp=true`. Nevertheless every protected request returns sanitized `503 portal_not_ready` and no identity method executes. Separate tests assert the unchanged HTTPS/CSRF guard can accept a valid same-origin request in isolation (avoiding false positives due to CSRF denial), and offline witness errors are sanitized.

**Important limitation:** The F382/F383 deny-only guard is *not deployable*; because it blocks every handler, it also blocks logout/revoke inside the controller. A future operational design MUST allow safe and durable revocations even during independent-witness outages, while never serving protected resources. This cannot be made safe merely by switching a feature flag or accepting a LAB status as a grant. All routes here are test-only; no real auth/checkout route is enabled on production.

GitHub Actions runs PHP 8.3/8.4 tests of these actual HTTP controllers, the F382 negative-only gate, the existing browser HTTP test suite and default-closed routes. No external Cloudflare host, D1, real credentials, SQL migration, VPS, DNS, public serving, merge or cost. Issue #64 remains OPEN/NO-GO.
